## BoxCopilot v2.0.0

Größtes Update seit v1.6.0: Spring Boot 4.1, umfassendes Security-Hardening, Login-Throttling, gehärtete Container und CI mit E2E-Tests. **Enthält Breaking Changes.** Vor dem Update bitte die Upgrade-Hinweise lesen.

### Highlights

- **Spring Boot 4.1** (Spring Framework 7, Security 7, Hibernate 7, Flyway 12, Jackson 3, Spring AI 2). Boot 3.5 ist seit 2026-06-30 ohne Support.
- **Login-Throttling pro Client-IP** statt Account-Sperre pro Benutzername. Antwort `429` mit `Retry-After`.
- **Passwort-Reset beendet Sessions**, invalidiert Magic-Links und entzieht MCP-Zugriff.
- **Erster OIDC-Login braucht Admin-Freigabe.**
- **Magic-Login-Tokens werden als SHA-256-Hash gespeichert.**
- **Share-Links widerrufbar** (`POST /api/v1/boxes/{id}/rotate-share`); Image-Tokens rotieren bei Löschen, Ersetzen und Verschieben.
- **Sichere Uploads:** max. 25 Megapixel, begrenzte parallele Dekodierung, saubere 400/503-Antworten, Bilder werden beim Löschen einer Box entfernt.
- **Gehärtete Container:** Backend mit read-only Root-FS, Memory-Limits, Healthchecks; Frontend mit CSP (standardmäßig `enforce`), HSTS, `X-Frame-Options: DENY`, `X-Forwarded-For`-Überschreibung in nginx.
- **Prod-Guards:** Start verweigert mit Dev-Profil, H2, Default-Admin-Passwort; `flyway.validate-on-migrate=true`, `ddl-auto=none`.
- **MCP:** Host/Origin-Prüfung, auditierte Typfehler, Input-Validierung in den Tools.
- **Frontend:** WCAG-AA-Kontraste, lazy Routen, Server-Validierungsfeedback, „Speichern und nächstes hinzufügen“, bessere Lade-/Fehlerzustände.
- **Qualität:** GitHub-Workflow (Backend, Frontend, E2E-Browser-Journey, sticky PR-Kommentar), Autorisierungs-Regressionsmatrix, Security-Audit-Bericht.

### Upgrade (BREAKING)

Reihenfolge einhalten.

1. **Backup:** Datenbank-Dump **und** `./images` (siehe `docs/ops/backup-restore.md`).
2. **`flyway repair` einmalig ausführen.** Die Migrationen V6, V9 und V10 wurden nach Release geändert; mit `validate-on-migrate=true` schlägt sonst der Checksum-Check beim Start fehl.
3. **`ADMIN_PASSWORD`** in Produktion mindestens 12 Zeichen (nicht leer, nicht `admin`). Passwörter im Admin-Panel: 12–128 Zeichen.
4. **Verzeichnisrechte:** Backend läuft als uid 10001.
   ```bash
   mkdir -p logs images && sudo chown -R 10001:10001 logs images
   ```
5. **Proxy-Konfiguration:** `TRUSTED_PROXY_PATTERN` (Java-Regex, nicht CIDR) und `REAL_IP_FROM` auf das `traefik-proxy`-Netz abstimmen. Bei falschem Wert teilen sich alle Clients einen Throttle-Zähler.
6. **Umgebungsvariablen prüfen** (`.env.example`): `SESSION_COOKIE_SAME_SITE`, `APP_LOGIN_THROTTLE_*`, `APP_IMAGE_MAX_CONCURRENT_UPLOADS`, `CSP_MODE`, `HSTS_ENABLED`. Mit `APP_MCP_ENABLED=true` müssen die Origins von `VITE_API_BASE_URL` und `BACKEND_URL` identisch sein.
7. **Postgres** ist auf `postgres:15.19` (Debian 13) gepinnt. Bei laufendem Debian-12-Image `postgres:15.19-bookworm` pinnen oder Text-Indizes per `REINDEX` neu aufbauen.
8. **Starten:** `docker compose build && docker compose up -d`. Flyway wendet V15, V16 und V17 an.
9. Alle Nutzer müssen sich **einmal neu anmelden**.

### Änderungen im Verhalten

- Account-Sperre und `unlock`-Endpoint entfallen. Deaktivieren von Benutzern bleibt.
- Letzter aktiver Admin kann nicht mehr degradiert, deaktiviert oder gelöscht werden.
- Eigenes Passwort zurücksetzen loggt aus.
- `POST /api/auth/logout` antwortet `200` mit `{"redirectUrl": ...}` statt Redirect.
- **V17 löscht alle Magic-Login-Tokens.** Bereits ausgegebene Links ungültig, neue erzeugen.
- Öffentliche Bild-URLs: `Cache-Control: public, max-age=3600` (vorher 1 Jahr, immutable). Alte geteilte Bild-Links werden nach Rotation ungültig.
- Eingaben begrenzt: Box-Beschreibung 5000 Zeichen, Bulk-Move 500 IDs, Suchtext 100 Zeichen (länger → 400), Suchergebnisse 200.
- JSON-Schlüssel in REST- und MCP-Antworten alphabetisch sortiert (Jackson 3). `tools/list` enthält zusätzlich `$schema`.
- Fehlende Parameter oder Multipart-Teile → `400` statt `500`; nicht vorhandene öffentliche Bilder → JSON-`404`.
- `APP_MCP_ENABLED` ist der einzige MCP-Hauptschalter.
- Session-Ablauf: 30 Minuten nach letzter Nutzung (unverändert).

### Entfernte Endpoints

- `GET /api/v1/items` → `GET /api/v1/items/box/{boxUuid}` oder `GET /api/v1/items/search`
- `GET /api/v1/box-numbers/status`
- Admin-API: `unlock`

### Bekannte Einschränkungen

- Login-Throttle liegt im Backend-Prozess: nicht replikatübergreifend, Reset bei Neustart. Ein Backend-Replikat betreiben.
- Clients hinter gleicher NAT-Adresse teilen sich das Kontingent.
- Nextcloud-Logout-Rücksprung hängt von Nextcloud ab.

### Rollback

DB-Dump zurückspielen nur, wenn Daten seit dem Update verworfen werden sollen. Zwingend: Backend stoppen, Redis-Sessions löschen, vorherige Images starten.
```bash
docker exec boxcopilot-redis sh -c "redis-cli --scan --pattern 'spring:session:*' | xargs -r redis-cli del"
```
Mit dem neuen `docker-compose.yml` braucht ein altes Image `user: "0:0"` und `cap_add: [DAC_OVERRIDE]`.
